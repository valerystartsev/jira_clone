# Руководство по работе с репозиторием

## Структура проекта и организация модулей

Репозиторий содержит Jira-подобное приложение, разделённое на два пакета:

- `api/` — сервис Node/Express на TypeScript. Размещайте маршруты в `src/routes.ts`, обработчики — в `src/controllers`, модели — в `src/entities`, код работы с базой данных — в `src/database`, а повторно используемую логику — в `src/utils`.
- `client/` — React-приложение. Модули маршрутов находятся в `src/Auth` и `src/Project`; общий код размещайте в `src/shared`, а глобальную настройку и ресурсы — в `src/App`.
- Сквозные тесты браузера находятся в `client/cypress/integration`. Файлы поддержки Jest — в `client/jest`.

Импорты клиентского модуля должны обращаться только к этому модулю или к `client/src/shared`, как описано в `client/README.md`.

## Команды сборки, тестирования и разработки

Если не указано иное, запускайте команды из корня репозитория:

- `npm run install-dependencies` устанавливает зависимости корневого проекта, API и клиента.
- `npm run build` собирает API на TypeScript и клиентский Webpack-бандл для production.
- Используйте Node 24. Создайте базы PostgreSQL `jira_development`, `jira_api_test` и `jira_test`, настройте `api/.env` по образцу `api/.env.example`.
- `npm run start:dev` запускает API на `http://localhost:3000` и клиент на `http://localhost:8080`.
- `npm run test:api` запускает HTTP-тесты API с Supertest на отдельной базе `jira_api_test`; запущенные серверы не нужны.
- `npm run test:jest` запускает клиентский Jest; сейчас файлов тестов Jest нет, команда успешно сообщает о 0 тестах.
- Для Cypress запустите `npm run start:cypress` в одном терминале, дождитесь готовности серверов и выполните `npm run test:cypress` (без интерфейса) или `npm run test:cypress:open` (с интерфейсом) в другом. Cypress использует `jira_test`. Для WSL/Linux при отсутствии `libXss.so.1` установите пакет `libxss1`.
- Для остановки API и клиента нажмите `Ctrl+C` в терминале с `start:dev` или `start:cypress`. При раздельном запуске остановите каждый процесс в его терминале; окно Cypress закройте отдельно. PostgreSQL останавливайте отдельно только при необходимости.

## Стиль кода и соглашения об именовании

Используйте отступы в два пробела, одинарные кавычки, висячие запятые и ширину строки 100 столбцов. Запускайте `npm run pre-commit`, чтобы применить ESLint и Prettier к подготовленным к коммиту файлам. Для компонентов и сущностей используйте `PascalCase`, для функций и переменных — `camelCase`, а названия папок функций должны соответствовать названиям маршрутов.

## Рекомендации по тестированию

Называйте спецификации Cypress по пользовательскому сценарию, например `issueCreate.spec.js`. Добавляйте сценарии в `client/cypress/integration`; при необходимости сбрасывайте или заполняйте тестовую базу данных. HTTP-тесты API находятся в `api/test` и сбрасывают только `jira_api_test`. Jest настроен для модульных тестов клиента, но таких тестов пока нет.

## Коммиты и запросы на включение изменений

Используйте короткие повелительные темы коммитов, например `Update README.md` или `Readme formatting`, в соответствии с существующей историей. Этот исходный репозиторий не принимает pull request (`CONTRIBUTING.md`); сопровождающим следует делать fork и отправлять изменения в собственный репозиторий. При работе с fork описывайте изменения поведения, выполненные тесты и изменения конфигурации; для визуальных обновлений добавляйте скриншоты интерфейса.

## Безопасность и конфигурация

Храните учётные данные базы данных и другие секреты в `api/.env`; не добавляйте их в репозиторий. Используйте отдельную базу `jira_test` для Cypress, чтобы тестовые данные не затрагивали данные разработки.
